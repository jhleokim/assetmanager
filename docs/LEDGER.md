# 가계부 — 설계와 근거

디어나 가계부 ver7.1.0(구글 시트 템플릿)을 이 앱의 [가계부] 탭으로 옮기면서, 시트가 수식으로 흉내 내던 것을
데이터 모델과 함수로 다시 세웠다. 계산은 전부 `core/ledger.js`(순수 함수, `core/ledger.test.js` 31건), 화면은 `app/ledger.js`.

## 1. 가계부의 정석 — 무엇을 지켰나

| 원칙 | 템플릿 | 이 앱 |
|---|---|---|
| **거래는 한 표에** 날짜·금액·대분류·소분류로 | 월별 시트 12장 + 시트마다 표 2개 | `entries` 한 배열. 월별·연간은 그 표를 잘라 보는 뷰 |
| **저축은 지출이 아니다** | 총 지출 = 수입·저축 제외 (맞음) | 종류 `income / saving / expense` 를 대분류가 결정 |
| **이체는 어디에도 넣지 않는다** | 개념 없음 → 카드대금 결제를 적으면 이중 계산 | 종류 `transfer`. 합계·비중·예산 어디에도 안 들어감 |
| **항등식** 수입 − 지출 − 저축 = 잔여 | 없음 | 월·연 화면에 "잔여" 카드로 항상 표시. 테스트로 고정 |
| **회계월**은 월급날 기준으로 | 시작일 설정 (29~31일이면 다음 달 1일로 튐) | 시작일 1~28. 25일이면 1/25~2/24 가 "1월" |
| **필수 항목이 비면 집계하지 않는다** | 안내문만 있고 조용히 누락 | 저장 시점에 거부하고 이유를 보여준다 |
| **고정지출은 매달 다시 치지 않는다** | 결제일 관리 시트는 메모일 뿐 | 규칙(`recurring`) → 기간당 1건씩 생성, 중복 방지 |
| **예산은 대분류별·월별**, 속도까지 | 수입/저축/지출 3개 목표만 | 대분류별 월 예산 + 경과 일수 대비 속도(pace) 경고 |
| **예비비는 별도 주머니** | 별도 시트, 총 지출에 합산 | 입금 = 저축/예비비, 지출 = 예비비/분류. 월 지출과 분리하고 순저축 = 저축 − 예비비 지출 |
| **평균은 지난 달 수로** | 요약 Data 시트가 오늘 위치를 찾아 나눔 | `annual().elapsed` — 연도가 끝나면 12 |
| **지운 분류의 옛 항목을 잃지 않는다** | 분류 바꾸면 수식 깨짐 (업데이트 버튼 필요) | 연간표에 "설정에 없음"으로 계속 표시 |
| 무지출 Day | 수동 색칠 | 변동지출 0원인 날을 자동 계산. 고정지출·예비비·미래일 제외 |

### 왜 이체가 중요한가
신용카드로 5만 원을 쓰고(지출 5만), 다음 달 카드대금 5만 원이 통장에서 빠진다. 후자를 지출로 적으면 같은 돈이 두 번
잡힌다. 통장 잔액과 가계부를 맞추려면 카드대금·계좌 간 이동은 **이체**로 적어야 한다. 지출은 카드를 긁은 날에 이미
잡혔다(발생주의). 이 앱은 이체를 받아 두되 어떤 합계에도 넣지 않는다.

### 예비비 계산이 이중이 아닌 이유
1월에 예비비 50만 원 입금(저축 +50만), 3월에 예비비로 여행 30만 원(예비비 지출 30만).
- 1월: 저축 50만 → 잔여식에 반영. 통장에서 실제로 50만이 빠졌다.
- 3월: 월 지출에는 안 넣는다(예비비 통장에서 나갔으므로 생활비 통장 잔여는 변하지 않는다). 대신 순저축 = 저축 − 30만.
연간으로 보면 저축 50만 − 예비비 지출 30만 = 순저축 20만 = 예비비 잔액 증가분. 정확히 맞아떨어진다.

## 2. 데이터 모델 (봉투 v3)
서버(D1)는 바뀌지 않았다. 가계부는 자산과 같은 암호화 봉투 안 `ledger` 에 산다.
```
db.ledger = {
  settings: { startDay, methods[], tags[], cats[{name, kind, subs[], fixed?, fund?}], budgets{}, fundBudgets{}, updatedAt },
  entries:  [{ id, date, amount(정수 원, 환불은 음수), kind, cat, sub, memo, method, tag, fund, rule?, updatedAt }],
  recurring:[{ id, name, amount, cat, sub, day(1~31), method, active, updatedAt }],
  events:   [{ id, period:"YYYY-MM", date, budget, memo, updatedAt }]
}
```
- `kind` 와 `fund` 는 대분류에서 자동으로 정해진다 (`fromCat`). 사용자는 종류를 따로 고르지 않는다.
- 병합(`store.merge`)은 id + updatedAt, 삭제는 `tomb["ledger.entries:ID"]`. 설정은 updatedAt이 최신인 쪽.
- `budgets` 의 `_income/_saving/_expense` 는 템플릿의 "목표 관리" 세 값.

## 3. 템플릿 → 앱 대응

| 시트 | 앱 |
|---|---|
| 설정 | [가계부 설정] 기본·분류 |
| 월별시트 1~12 | [월별] (시작일 기준 기간 이동) |
| 이달의 고정지출 내역 | 고정지출 대분류 + [고정지출 채우기] |
| 목표 관리 / 태그별 / 결제수단별 / 무지출 Day / 이달의 이벤트 | [월별] 우측 |
| 통합시트 | [연간] |
| 예비비 | [예비비] |
| 결제일 관리 | [가계부 설정] 고정지출 규칙 |
| 자산관리 | 옮기지 않음 — [자산 목록]·[자산 추이]가 더 정확히 한다 (시세·이자·거래 반영) |
| 통장관리 · 카드 관리 | 옮기지 않음 — 계좌번호·카드번호 원본 보관은 이 앱의 개인정보 원칙(`docs/DATA-PRIVACY.md`)과 맞지 않는다 |

## 4. 엑셀에서 가져오기
```
pip install openpyxl
python3 tools/import_dieona.py 가계부.xlsx > ledger.json     # stderr 에 요약
```
앱 [설정] → [JSON 불러오기] 로 병합. 가져오기 전에 현재 상태를 자동으로 백업 파일로 내려준다.
`--sample` 을 붙이면 '월별시트 샘플페이지'도 읽는다(검증용: 수입 7,600,000 / 지출 2,435,000 / 저축 2,100,000 이 나와야 한다).
